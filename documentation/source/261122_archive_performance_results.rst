결론
----

가장 큰 개선은 로컬 UDF Bridge 생성이다. 동일한 64 MiB 파일로 바이트 단위로 동일한 이미지를 만드는 시간이 378.5 ms에서 154.5 ms로 59.2% 줄었다. SMB 루프백의 작은 파일 복사는 29.0% 단축됐다. 외부 도구와 직접 비교한 작업에서는 7z.exe, oscdimg, robocopy가 모두 빨랐다. 상세 계획의 종단 성능 인수 조건은 미충족이다.

구현과 결과 해석
----------------

* **7z·ZIP 생성** — 새 압축 파일에서는 코덱이 읽는 입력으로 SHA-256을 계산하고, 결과를 해독하면서 항목의 크기와 해시를 대조한다. 인코더가 건너뛴 범위는 별도로 읽는다. 기존 압축 파일 갱신에는 기존 검증을 유지한다. 하나의 생성 작업에서 여러 결과를 만들 때 승인된 백엔드와 호스트를 재사용한다. 원격 입력의 읽기 버퍼는 사용할 때 할당한다.
* **본체 직접 실행** — 같은 개선 빌드에서 첫 호스트 호출 200.5 ms, 재사용 99 ms, 프로세스 내 SDK 직접 호출 90 ms(p95 92 ms)였다. 직접 호출도 7z.exe보다 3.75배 오래 걸렸다. 직접 호출은 테스트 실행 파일에서 수행했으며 제품의 플러그인 승인 절차를 포함하지 않는다. 호스트 재사용을 제품에 적용했고 본체 직접 로딩은 기본 경로로 채택하지 않았다. 직접 호출의 잔여 시간에서 해독 검증·해시·코덱 각각의 기여도는 이번 계측으로 확정할 수 없다.
* **ISO 생성·읽기** — UDF·Joliet·Primary가 공유하는 데이터 구간은 한 번 원본과 대조하고 각 이름 공간의 항목·크기·extent 검증은 유지한다. 데이터 구간을 물리 순서로 확인하고 호출자 버퍼로 직접 읽는다. 끝부분 기록은 본문 기록 뒤로 옮겼다. Bridge에서 원본 본문을 읽는 논리 횟수는 기록을 포함해 4회에서 2회로, 생성 이미지 본문 재독은 3회에서 1회로 줄었다. ISO 9660은 처음부터 이름 공간이 하나여서 실측 개선 폭이 작았다. ISO 추출 비교에서는 같은 64 MiB를 디스크로 복원하는 시간이 18.8% 줄었다.
* **SMB·임시 경로** — 작은 파일의 준비 작업에 최대 네 작업자를 사용하고 기존 충돌 판정·순서에 따른 확정 절차를 유지한다. 개선 빌드의 직렬 복사는 9,419.7 ms, 자동 병렬은 6,726.2 ms였다. 원격 목적지에 대해 환경 변수 HC_ARCHIVE_LOCAL_STAGE=1로 로컬 임시 디스크에서 생성한 뒤 원격 목적지에 기록하는 선택 경로도 구현했다. 기본값은 목적지 볼륨에서 준비한다. 두 방식 모두 생성·재시도 기능을 검증했고 경로별 속도 우위는 미판정이다.

비교 조건과 검증 범위
---------------------

* Windows 11 게스트, Qt 6.12.0, MSVC 2026 x64 Release. 비교 대상은 기존 설치본의 호스트·ISO DLL과 작업 트리(HEAD 0b800981 및 미커밋 변경)의 검증 빌드다. 7z는 같은 테스트 실행 파일과 같은 코덱 DLL로 비교했다. SMB의 기존값은 병렬 적용 전 직렬 경로를 실행한 값이다.
* 압축·ISO는 기존/개선/개선/기존 순서를 15번 반복했다. 각 실행 안에서 7z 첫 호스트 → 재사용 → 직접 → CLI, ISO 9660은 HC → oscdimg 순서다. OS 캐시는 비우지 않았다. 첫 호스트는 프로세스 최초 사용을 뜻한다. UI 입력부터 작업 큐·최종 파일 공개·완료 통지까지는 측정에 포함하지 않았다. 동일 빌드끼리의 A/A 비교가 없어 작은 차이에 대한 통계적 인수 판정은 보류한다.
* 7z는 반복 바이트 8 MiB, 7z.exe 26.03, LZMA2 레벨 1, solid·필터 해제. 각 결과는 1,915바이트였고 시간 측정 뒤 7z.exe x -so로 복원한 전체 내용을 비교했다. HC는 생성 중 해독 검증도 수행한다. ZIP 생성의 외부 대비 시간은 미측정이다. 7z·ZIP 추출은 7z.exe로 만든 8 MiB 단일 항목을 사용했다. HC는 백엔드 생성·열거·디스크 추출·백엔드 해제, CLI는 프로세스 시작부터 종료까지 재고 복원 내용 전체를 대조했다. ZIP 추출의 1 ms 차이는 개선 효과로 단정하기 어렵다.
* ISO는 반복 바이트 64 MiB 한 파일이다. Bridge 결과 68,186,112바이트의 SHA-256은 모든 회차에서 df09bf756ce076f2e174e51b847fb12ea7aced336997132fe9acd423f5da288d였다. ISO 9660은 oscdimg 2.56과 같은 파일을 넣고 각 이미지에서 전체 본문을 읽어 대조했다. HC 이미지 67,182,592바이트, oscdimg 이미지 67,151,872바이트로 파일 배치는 다르다.
* ISO 추출은 같은 oscdimg 생성 이미지(64 MiB 영 바이트 단일 항목)를 사용했다. 게스트에서 1 MiB 버퍼로 ISO DLL의 열기·항목 찾기·읽기·파일 쓰기·닫기와 7z.exe x의 프로세스 실행부터 종료까지를 측정했다. 기존/개선/CLI/CLI/개선/기존 순서를 15회 반복하고 매회 복원 SHA-256을 확인했다. HC 측에는 작업 큐·WCX 호스트 시간이 빠져 있다.
* SMB는 게스트의 같은 루프백 관리 공유에서 파일 235개, 하위 디렉터리 41개, 총 2,114,030바이트를 복사했다. 구현별 세 번 측정했다. 검증은 복사한 파일 수·디렉터리 수·총 바이트 대조다. 루프백에는 실제 NAS의 네트워크 왕복 지연이나 RDP 리디렉션 채널이 포함되지 않는다.
* VM 회귀 결과는 7z 생성·갱신·실패 원자성 13건, ISO 전체 17건, 기본 전송 11건 통과다. SMB 목적지 7z·ZIP·ISO 생성과 부분 재시도는 로컬 준비 on/off 각각 6건 통과다. 건수에 QtTest 초기화·종료가 포함된다.

-------------

남은 인수 항목
--------------

VM의 콘솔 세션에는 RDP 리디렉션 드라이브가 없었고 VM에서 실 NAS 공유에 접근할 수 없었다. 실제 SMB·RDP 양방향과 로컬/SMB/RDP 간 9개 조합, 원격에서 임시 준비 전략별 시간, ZIP·7z·ISO 해제의 종단 성능은 미확인이다. 대용량·비압축성·다수 소형 파일 압축 코퍼스, UI 완료 시점, A/A 잡음, 독립 실행 순서 교차, 단계별 CPU·I/O도 상세 계획의 미완료 항목이다. 다음 최적화의 우선순위는 7z 직접 호출에 남는 66 ms의 해독·해시·코덱 시간 분해와 SMB에서 파일별 준비·확정 왕복 수 측정이다.
